# AI-Based Predictive Energy Management — thesis code

Forecasts 15-minute industrial electricity consumption (UCI *Steel Industry Energy Consumption*, ID 851, CC BY 4.0)
with a naive baseline, Linear Regression, Random Forest, XGBoost, LSTM and BiLSTM, and carries the best forecast into a
rule-based load-shifting scenario (cost, CO2, peak demand).

## Setup
```bash
python3.12 -m venv .venv312   # Python 3.12: TensorFlow crashes on Apple's system Python 3.9
.venv312/bin/pip install -r requirements.txt
brew install libomp            # macOS only: OpenMP runtime needed by XGBoost
```
The raw file is included at `data/raw/Steel_industry_data.csv` (UCI Machine Learning Repository, dataset 851,
Sathishkumar V E and Shin, C., 2021, DOI 10.24432/C52G8C, licence CC BY 4.0). Its SHA-256 is checked against `src/config.py`.

## Reproduce everything
```bash
.venv312/bin/python run_all.py          # all phases, raw CSV -> results/
.venv312/bin/python -m pytest tests      # leakage, split-ordering and energy-conservation tests
```
Every script also runs standalone, e.g. `.venv312/bin/python -m src.scenario`.

## Design decisions enforced in code
- Target `Usage_kWh` at t+1; every feature uses information up to t (tested in `tests/test_leakage.py`).
- `CO2(tCO2)` is never a feature; electrical variables enter only at t (one step before the target).
- The raw file stores the 00:00 reading under the day it closes; the loader moves it to the next calendar day, after which spacing is uniform.
- Tree models and sequence models see the same 96-step (24 h) history: lags y(t)…y(t-3), y(t-95) and 4/96-step rolling statistics vs. a 96-step window.
- Chronological 70/15/15 split, scaler fitted on training data only, fixed seeds (`src/config.py`), three seeds for LSTM/BiLSTM.
- The scenario function `src/scenario.run_scenario` is the single implementation for the pipeline and the prototype.

## Environment used
Apple M2, macOS, CPU only, Python 3.12; library versions are written to `results/metrics/run_info.csv` on every run.
